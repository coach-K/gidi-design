## Canvas
- CanvasScaler: Scale With Screen Size, reference **1920×1080**, match **height (1.0)**, landscape only. On a 2340×1080 phone, 1 ref px = 1 device px; at 3x, **3 px = 1 dp**.
- Safe area: desktop 32 px margin. Phone: `Screen.safeArea` (mock: left/right 132 px = 44 dp notch inset, bottom 63 px = 21 dp home indicator, top 24 px). All HUD lives inside the safe rect.
- Minimum touch target **144 px (48 dp)**. Font: Plus Jakarta Sans Bold.

## Camera (current build, no change)
From `TailCameraFollow` + `UI/HudLandscapeConfig.cs` on team-branch:
- URP **perspective** camera, pitch **65°**, yaw 0, X locked, follows the crowd on Z.
- Standard stages: height **15 m**, focus offset Z **−5 m**, vertical FOV **52°**.
- Wide stages (lane count ≥ `wideStageLaneCount` = 8, e.g. L8–L10; the mock shows L5, a standard stage): height **20 m**, FOV **58°**.
- Unity FOV is vertical, so 19.5:9 phones see more lane length than 16:9 desktops at the same height.
- Traffic spawns `spawnBeyondViewMargin` (3 m) beyond the visible half-width, so cars enter from the screen edge.

## OWA! button states and pip spec
- **Cap 3**, always exactly 3 round pips (18 px Ø, 2 px outline, 7 px gap), left to right.
- **Filled** pip: Owa teal `#59D9B8` fill and outline. One charge ready.
- **Partial** pip: conic fill clockwise from 12 o'clock showing refill progress of the next charge (only the first non-full pip can be partial). Teal outline.
- **Empty** pip: ink `rgba(20,22,30,.55)` with a 2 px cream outline at 55%.
- **Ready** (≥1 full charge): gold outline, gold label; tap fires Owa!.
- **Disabled** (0 full, nothing refilling, or not unlocked before L2): grey outline at 55%, grey label at 60%, no shadow, all pips empty, tap ignored.
- **Highlight** (just unlocked / tutorial / toast points at it): extra 6 px gold glow ring.
- Mockups: partial `hud-desktop` / `hud-phone` (2 + ½), full `hud-endless-*` (3), one empty `hud-power-*` (2 of 3), highlight `hud-toast-*` (1 of 3), disabled `hud-warn-*` and onboarding, tablet 1 + partial + empty.

## Bag (GPP-021): 4 shared slots, tap to activate

**Tap feedback.** Scale 1 → 0.92 (80 ms) → 1.0 (120 ms ease-out back); light haptic (iOS `UIImpactFeedbackGenerator.light`, Android `VIRTUAL_KEY`); sound `sfx_bag_slot_tap`, then the item's own cue. Denied tap (cooldown / disabled / empty): 6 px horizontal shake 3× in 240 ms, `sfx_bag_denied`, no haptic.

**Full bag on pickup (chosen behaviour).** The item is NOT picked up and stays on the curb (pickup marker stays lit); all 4 slots shake (6 px, 240 ms) with the orange `bag_slot_full` frame for 600 ms; toast `panel_toast_normal` with `icon_bag` tinted #FF7A1A: "Bag full · tap a slot to use one" (2 s, one toast per 4 s max). Exception: a stackable item whose type is already in the bag below its cap stacks normally.

**VIP Siren anti-exploit.** One per level (after use the slot shows Disabled "Used this level" until the next level); 8 s cooldown after the 5 s effect ends; price per run 120 → 180 → 270 (stays 270), resets at cash-out. Base Camp tile shows the next price ("next ₦180"); states in `siren-states-*`.

**Base Camp.** Bag strip bottom-left (120 slots, "YOUR BAG n/4"), tiles: new type with no free slot → `btn_buy_full` "Bag full"; same type below cap → "+1 to stack"; Siren bought this level → "Used this level" + next price. Level intro shows the carried-over bag (see `../unity/screens/intro/README.md`, bag row).

**Open question.** OWA! stays a separate button above PICK UP (current build) AND OWA charges sit in the bag (mockups show both: the button fires a charge, the slot shows the count). Confirm: keep both, or drop the OWA! button and use only the slot (frees the PICK UP stack).

## Power-up active + Owa countdown ring (RT-118, G-Prototype PR #107)
Mockups: `hud-owa-*` (Owa freeze running while a Malta chip runs), `owa-ring-states-*`. Code: `ActivePowerUpHudRules`, `MobileControlsView.SetOwaActive(remaining01, totalSeconds)`, called from `GameHudController.RefreshAll` with `traffic.OwaRemainingNormalized` and `LevelManager.owaShoutFreezeDuration` (4 s).

| Power-up (`HudPowerUp`) | `ActiveIndicator` | What the HUD draws |
|---|---|---|
| Owa | `OwaButtonRing` | ring around the OWA! button (below) |
| Maltina / PureWater / Siren | `TimerChip` (`ActiveChipKind` Malta / PureWater / Siren) | existing timer chip under the top band, gold ring + `Malta · 4s` caption (PR #85, unchanged) |
| Bribe (CHANGE) | `StockCountOnly` | CHANGE pips drop by one, nothing else |
| Whistle | `Removed` | nothing (removed in #39) |

**Owa ring (`FreezeTimer` Image)**
- Sprite: reuse `ring_powerup_timer_fill` (white, tinted at runtime). Optional track: `ring_powerup_timer_track` at the same size (white 15%), only while the ring shows. No new sprite needed.
- Size **140 px Ø** at 1080 (`OwaRingDiameter`), centred on the 144 touch box, i.e. just outside the 120 px face and its glow. The 170 px sprite scaled to 140 gives an ≈8 px stroke (`OwaRingThickness`).
- Image Type Filled, Radial 360, origin Top, **counter-clockwise** (`fillClockwise = false`), `fillAmount = OwaRingFill(remaining01)`; raycastTarget off; draws above the rim and below the label.
- Colour: Owa teal `#59D9B8` (`GameUiTheme.OwaTeal`). In the last `PowerUpChipRules.WarningSeconds` it turns `GameUiTheme.Danger` (Okabe-Ito vermilion), paired with a shape cue: add a 1 Hz scale pulse (1.00 → 1.06) on the ring so it doesn't rely on colour alone.
- Visible only while `remaining01 > PowerUpChipRules.MinActive`; hide instantly at the end (no fade needed).
- **Pips keep showing charges left** (the charge was spent on tap, so a 2-charge button shows 1 filled pip while the ring runs). Button stays tappable only if another charge exists; a second tap while frozen is queued/ignored per `_owaQueued` (no visual change).
- Bag (GPP-021): if OWA! moves into the bag, the same ring draws around the Owa bag slot at 124 px (`bag_slot_active` + the ring), same colours.
